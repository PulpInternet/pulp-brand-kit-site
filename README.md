# Pulp Brand Kit, the site

The Pulp Brand Kit as a website: every part of the kit, every board on the canvas, all the rules, the palette, the social posts and the downloads, with search on every page. It is plain static files, so GitHub Pages serves it as it is.

## What is here

| Path | What it is |
|---|---|
| `index.html` | Home |
| `kit/` | The fifteen parts of the kit, each with its contents and boards |
| `boards/` | Every board on the canvas; each opens large in a viewer with its own link |
| `rules/` | Every rule, filtered by check and scope |
| `colors/` | The palette and every mode of every property |
| `social/` | The post templates and the first five posts on each platform, with captions |
| `downloads/` | Marks, symbols, icons, prints, plates, fonts and the machine pack |
| `search/`, `search.json` | The search page and its index |
| `404.html` | The page GitHub Pages shows for a missing path |
| `.nojekyll` | Tells GitHub Pages to serve the files as they are |

Do not edit these files by hand, this README included. They are generated from the kit repo, `pulp-brand-kit` (`generator/kitsite_readme.md` and `generator/kitsite.py`), and every rebuild replaces them.

## How to put it live

**1. Create the repo on GitHub.** With the GitHub CLI:

```sh
cd ~/dev/pulp-brand-kit-site
gh repo create pulp-brand-kit-site --public --source=. --remote=origin --push
```

Or on github.com: New repository, name it `pulp-brand-kit-site`, leave it empty (no README), then:

```sh
cd ~/dev/pulp-brand-kit-site
git remote add origin https://github.com/<your-account>/pulp-brand-kit-site.git
git push -u origin main
```

**2. Turn on Pages.** On the repo: Settings, Pages, Build and deployment. Set Source to Deploy from a branch, Branch to `main`, folder `/ (root)`, and Save. Or with the CLI:

```sh
gh api -X POST repos/<your-account>/pulp-brand-kit-site/pages -f "source[branch]=main" -f "source[path]=/"
```

**3. Open it.** After a minute or two it is live at:

```
https://<your-account>.github.io/pulp-brand-kit-site/
```

The Pages settings show the address and the state of the last deploy. Every link in the site is relative, so it works at that address and on a custom domain alike.

**Optional: a custom domain**, such as `brand.pulp.com.ai`. Add a DNS record for the subdomain:

```
CNAME   brand   <your-account>.github.io
```

Then in Settings, Pages, Custom domain, enter `brand.pulp.com.ai`, save, and tick Enforce HTTPS once the certificate is issued. GitHub writes a `CNAME` file into the repo; the rebuild keeps it.

## How to update it

In the kit repo, rebuild everything, then rebuild the site and check it:

```sh
cd ~/dev/pulp-brand-kit
make all && make check
make kitsite
```

Then publish the new version:

```sh
cd ~/dev/pulp-brand-kit-site
git add -A
git commit -m "Kit site, $(date +%Y-%m-%d)"
git push
```

GitHub Pages redeploys on every push to `main`.

## Who can see it

A GitHub Pages site is public to anyone with the address, even when the repo is private. On GitHub Free, Pages needs a public repo; Pro and Team can publish from a private repo, and the site is still public. Only GitHub Enterprise Cloud can limit a Pages site to people in your organization. Publish only what may be public.

## Summary

Static files, generated by `make kitsite` in the kit repo. Push to `main` and turn on Pages from the branch root; every later push redeploys.
